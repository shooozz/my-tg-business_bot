# Бесплатные резервные копии в Google Drive

Подготовлен ежедневный бэкап базы без платного backup-тарифа VPS. Он ещё **не включён**: сначала нужны сервер, авторизация Google и контрольное восстановление. Бесплатный лимит Google — до 15 ГБ, общий с Gmail/Photos; проверьте фактическое свободное место в своём аккаунте. Стоимость сверх бесплатной квоты автоматически не подключаем.

## Что сохраняется

Согласованный SQLite-снимок заказов, платежей, товаров, переписки и очередей. Сначала проверяется integrity_check, затем gzip, шифрование rclone crypt и отправка на Google Drive. После загрузки выполняется обратное чтение с расшифровкой и сравнением. Только после этого удаляются устаревшие снимки: остаются последние 7 дневных и по одному за последние 4 недели (совпадающие копии не дублируются, всего не более 11). На VPS остаются последние 7 локальных снимков, включая снимки перед деплоем.

Удаление старых облачных копий окончательное, без корзины, чтобы они не расходовали бесплатную квоту. Скрипт затрагивает только имена своего формата внутри `market-crypt:my-tg-business_bot`. В эту папку не кладите посторонние файлы и не используйте её для другого магазина. Нельзя использовать `sync` для резервирования базы: это может перенести случайное удаление на резервную копию.

Фотографии/файлы поддержки остаются в Telegram, их содержимое не входит в снимок. Код восстанавливается из GitHub. Отдельно сохраните `.env` с `DATA_KEY`, пароль/salt шифрования rclone crypt и конфигурацию rclone в защищённом менеджере паролей или офлайн-копии. Не храните единственный ключ внутри зашифрованного им архива. OAuth-токен можно перевыпустить; утерянный пароль crypt не восстановить.

## Первичная настройка на VPS

Предполагается Ubuntu, пользователь `deploy` с доступом к Docker и уже выполненный деплой через `deploy/deploy.sh`. Файл `/opt/market/current-release` должен содержать SHA запущенного релиза. Не ставьте расписание до первого успешного деплоя.

1. Установите `rclone` из официального репозитория Ubuntu (`sudo apt install rclone`). На сервере под пользователем deploy:

```bash
install -d -m 700 /opt/market/backup
rclone config --config /opt/market/backup/rclone.conf
```

2. Создайте remote `gdrive`, тип Google Drive. Для личного бесплатного Диска используйте обычную OAuth-авторизацию своего аккаунта, не service account. Scope `drive.file` ограничивает доступ файлами, созданными этим приложением. На сервере без браузера выберите ручную авторизацию и следуйте показанной инструкции `rclone authorize` на своём компьютере. Не отправляйте токен в чат/GitHub. [Инструкция rclone](https://rclone.org/remote_setup/).

3. Создайте второй remote `market-crypt`, тип `crypt`, поверх `gdrive:MarketBackups`. Выберите стандартное шифрование имён и включите шифрование каталогов. Сгенерируйте стойкий пароль и salt, сохраните их вне VPS. [Инструкция crypt](https://rclone.org/crypt/). Не публикуйте Google Drive папку по ссылке.

4. Установите права и проверьте доступ. Эти команды не показывают секреты:

```bash
chmod 600 /opt/market/backup/rclone.conf
rclone --config /opt/market/backup/rclone.conf about gdrive:
```

Если используете собственный OAuth client Google, учитывайте предупреждение rclone о короткой жизни токенов приложения в режиме Testing; настройку нужно завершить для длительной фоновой работы. Не оставляйте автоматизацию на временном токене.

5. Из каталога развёрнутого релиза:

```bash
install -m 700 scripts/drive_backup.py /opt/market/backup/drive_backup.py
sudo install -m 644 deploy/market-backup.service deploy/market-backup.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl start market-backup.service
sudo journalctl -u market-backup.service --no-pager -n 30
```

При успешном завершении появится `/opt/market/backup/last-success`. Убедитесь в этом и выполните контрольное восстановление ниже. Затем включите ежедневный таймер:

```bash
sudo systemctl enable --now market-backup.timer
systemctl list-timers market-backup.timer
```

Расписание: ежедневно в 03:00 по Москве плюс случайная задержка до 5 минут. Пропущенный запуск выполняется после включения VPS (`Persistent=true`). При обновлении через deploy.sh скрипт резервирования обновляется автоматически; изменённые unit-файлы устанавливаются вручную.

## Контрольное восстановление без остановки магазина

```bash
rclone --config /opt/market/backup/rclone.conf lsf market-crypt:my-tg-business_bot
```

Выберите точное имя снимка из списка. В отдельном закрытом каталоге загрузите его командой `rclone copyto` через remote `market-crypt:`: rclone расшифрует содержимое. Распакуйте gzip и проверьте `PRAGMA integrity_check` через Python sqlite3. Сверьте количество заказов и тестово расшифруйте запись с сохранённым DATA_KEY в изолированной среде. Не заменяйте работающую базу ради проверки.

При реальной аварии сначала остановите приложение и сохраните текущий volume. Восстановите `.db`, прежний DATA_KEY и остальные настройки; только затем запускайте один экземпляр приложения. После восстановления сверьте платежи и заказы за время между снимком и сбоем с Telegram/Jaha: суточный бэкап может потерять до суток новых данных.

## Ошибки и ограничения

- При заполнении квоты или отзыве доступа задание завершится ошибкой, старые удалённые копии не очищаются до проверки новой. Очистка не освобождает место заранее — оставляйте запас хотя бы для одной дополнительной копии.
- Ошибка ставит уведомление в очередь админского бота. Если сам VPS/Docker/бот не работает, сообщение не сможет уйти: нужен внешний мониторинг для обнаружения полного отказа сервера.
- Журнал: `journalctl -u market-backup.service`. Он не выводит OAuth-токены, пароли и содержимое базы. Для диагностики сначала проверьте `rclone about`, актуальность входа и доступность Docker.
- При многодневных сбоях локальные снимки сохраняются и занимают диск. Следите за свободным местом.
- Бэкапы на том же Google-аккаунте подвержены потере аккаунта. Сохраните средства восстановления аккаунта и периодически скачивайте независимую офлайн-копию.

Источники: [лимит Google](https://support.google.com/drive/answer/9312312?hl=ru), [Google Drive backend](https://rclone.org/drive/), [проверка скачиванием](https://rclone.org/commands/rclone_check/).
